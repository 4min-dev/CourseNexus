## 🚨 Критические баги (требуют немедленного исправления)

### 1. **БАГ: SQL запросы используют несуществующую колонку `course_id`**
**Приоритет**: CRITICAL  
**Затронутые задания**: "Первое завершение", "Целеустремлённый", "Перфекционист", "Мастер завершений"

**Проблема**:
```sql
SELECT course_id
FROM lesson_progress
WHERE user_id = ${userId}
GROUP BY course_id
```

В таблице `lesson_progress` **НЕТ** колонки `course_id`. Есть только:
- `userId`, `lessonId`, `completed`, `completedAt`, `watchedSeconds`, `lastAccessedAt`

**Результат**: Ошибка в логах:
```
error: column "course_id" does not exist
```

**Решение**: Нужен JOIN через `lessons` → `course_sections` → `courses`:
```sql
SELECT cs.course_id, COUNT(*) as total_lessons, 
       COUNT(CASE WHEN lp.completed = true THEN 1 END) as completed_lessons
FROM lesson_progress lp
INNER JOIN lessons l ON l.id = lp.lesson_id
INNER JOIN course_sections cs ON cs.id = l.section_id
WHERE lp.user_id = ${userId}
GROUP BY cs.course_id
HAVING COUNT(CASE WHEN lp.completed = true THEN 1 END) = COUNT(*)
AND COUNT(*) > 0
```

### 2. **БАГ: Часовые пояса не учитываются (критично для временных заданий)**
**Приоритет**: HIGH  
**Затронутые задания**: "Ночной совёнок", "Ранняя пташка", все daily/weekly задания

**Проблема**:
- Все временные проверки используют серверное время (`new Date()`)
- Пользователь из Владивостока (GMT+10) не сможет получить "Ночной совёнок" (полночь-6 утра по серверному времени)
- Streak система использует `toDateString()` в серверном часовом поясе

**Пример**:
```javascript
const today = new Date();
today.setHours(0, 0, 0, 0); // Полночь ПО СЕРВЕРНОМУ ВРЕМЕНИ
```

**Решение**:
1. Добавить поле `timezone` в таблицу `users` (например, "Europe/Moscow", "Asia/Vladivostok")
2. Использовать библиотеку `date-fns-tz` для конвертации
3. Все временные проверки делать в часовом поясе пользователя

**Временное решение**: Документировать что все задания работают по московскому времени (UTC+3)

### 3. **БАГ: "Первооткрыватель" использует неправильную сортировку**
**Приоритет**: MEDIUM  
**Затронутое задание**: "Первооткрыватель" (первые 100 пользователей)

**Проблема**:
```javascript
const allUsers = await db.select({ id: users.id })
  .from(users)
  .orderBy(users.id); // ❌ UUID не гарантирует порядок регистрации!
```

UUID генерируются случайно (`gen_random_uuid()`), поэтому сортировка по `id` не соответствует порядку регистрации.

**Решение**:
```javascript
const allUsers = await db.select({ id: users.id })
  .from(users)
  .orderBy(users.createdAt); // ✅ Используем timestamp
```
