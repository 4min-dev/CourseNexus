## 🚀 Рекомендации по оптимизации

### 1. **Краткосрочные улучшения (быстрые победы)**

#### A. Кэширование (Redis/In-Memory)
```typescript
// Кэшировать список курсов на 5 минут
const cachedCourses = await cache.get('courses:list');
if (cachedCourses) return cachedCourses;

const courses = await db.query.courses.findMany();
await cache.set('courses:list', courses, 300); // 5 min TTL
```

**Эффект**: Снижение нагрузки на БД на 70-80%

#### B. Database Indexing
```sql
-- Индексы для быстрой выборки
CREATE INDEX idx_courses_platform ON courses(platform);
CREATE INDEX idx_courses_level ON courses(level);
CREATE INDEX idx_courses_year ON courses(year);
CREATE INDEX idx_purchases_user ON purchases(user_id);
```

**Эффект**: Ускорение запросов на 30-50%

#### C. Connection Pooling (уже реализовано ✅)
- Pool size: 20 соединений
- Idle timeout: 30 сек
- Connection timeout: 10 сек

### 2. **Среднесрочные улучшения (1-2 недели)**

#### A. CDN для статического контента
```
Cloudflare / Amazon CloudFront
├── Публичные видео-превью
├── Изображения курсов
└── Статические ассеты
```

**Эффект**: Снижение нагрузки на сервер на 60%, улучшение скорости загрузки на 3-5x

#### B. Response Compression
```typescript
import compression from 'compression';
app.use(compression({
  level: 6,
  threshold: 1024, // Сжимать только > 1KB
}));
```

**Эффект**: Уменьшение размера ответа на 70-80%

#### C. Query Optimization
```typescript
// Плохо: N+1 запросов
const courses = await db.query.courses.findMany();
for (const course of courses) {
  course.author = await db.query.users.findFirst({ where: eq(users.id, course.authorId) });
}

// Хорошо: 1 запрос с JOIN
const courses = await db.query.courses.findMany({
  with: { author: true }
});
```

## 🔥 Узкие места (Bottlenecks)

### 1. Database Connections (текущий лимит: 20 - соответствует лимиту Neon Serverless)
**Проблема**: При >100 пользователей возможна нехватка соединений

**Решение**:
- ⚠️ **НЕ** увеличивать pool size выше 20 (это лимит Neon Serverless)
- Использовать PgBouncer для connection pooling и мультиплексирования
- Реализовать кэширование (Redis/in-memory) для снижения запросов к БД
- Рассмотреть переход на Neon Pro при масштабировании (до 100 соединений)

### 2. Video Streaming
**Проблема**: При 30+ одновременных видео время ответа ~500ms

**Решение**:
- CDN для видео-файлов
- Adaptive bitrate streaming (HLS/DASH)
- Video compression и pre-processing

### 3. Cold Start (первый запрос списка курсов: 1.2s)
**Проблема**: Медленный первый запрос после restart

**Решение**:
- Warmup скрипт при старте сервера
- Persistent кэш (Redis)
